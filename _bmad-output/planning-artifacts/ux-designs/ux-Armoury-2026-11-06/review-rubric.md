# Spine Pair Review — Armoury

## Overall verdict
The pair is a clean, extractable contract: every `{path.to.token}` resolves (357 refs in DESIGN.md, 25 in EXPERIENCE.md), all 42 colour roles have hex values in both Light and `-dark`, the stated contrast table matches values I computed to ±0.05, and UJ-1/2/3 are covered verbatim with protagonist, steps, climax and failure path. The weak spot is **state coverage**. Four high-impact gaps would force downstream teams to invent product behaviour. (1) An Exposure "zero" cannot tell "no software has it" from "we don't know this ID yet", which gives false reassurance on CVE day. (2) No pattern covers a failed save of a review decision or any other mutation. (3) The unit of an "issue" is undefined when decisions differ across the places it affects. (4) The WCAG 2.2 AA claim cannot hold while every viewport under 1280px is undesigned. No critical findings.

## 2. Token completeness — adequate
Checked mechanically (`/tmp/rubric/tok.py`, `/tmp/rubric/con.py`). I parsed the frontmatter and resolved every `{a.b}` reference in both files: 0 unresolved, except the literal placeholder `{path.to.token}` (EXPERIENCE.md L18). All 84 colour values are valid 6- or 8-digit hex. All 42 light roles have a `-dark` pair, with no orphans either way. Every mock `:root` and dark-remap value equals the spine (the rgba→8-digit hex conversions also check out). I recomputed every contrast pair in DESIGN.md L500–520 and all match. The lowest text pair is text-3 on chip at 4.88. Tokens defined but never referenced: `forest-3`, `amber-wash`, `display-reserved`, `rounded.DEFAULT`, `button-height-sm`, `button-height-wide`.
### Findings
- **medium** Foreground colours for selected rows are only partly specified. `list-row` defines on-selection colours for title and secondary text, and `status-chip` has on-selection tokens. `exploited-text`, `kind-tag`, `licence-marker` and `table` (secondary/muted cells) do not (DESIGN.md L283, L298, L301, L403). In the mock they switch to `sage-hi` / `sel-chip` (mock CSS `.row.sel .atk.q`, `.row.sel .kind`, `.row.sel .lic`, `.table tr.sel .muted`). A consumer reading only the spine gets clay "Actively exploited" text on the forest selection at **1.96:1** (light) and text-2 on forest at **1.88:1**. Because the spine wins over the mock, those failing values would be the contract. *Fix:* add `on-selection-foreground: '{colors.sage-hi}'` to exploited-text, licence-marker and kind-tag (plus `on-selection-background: '{colors.sel-chip}'` on kind-tag), and `selected-foreground` / `selected-secondary` to `table`.
- **medium** Many component tokens are composite strings that a resolver cannot flatten. Examples: `'1px inset {colors.ink-line}'`, `'{typography.meta}, weight 500, {colors.text-3}'`, `'0 30px 70px -20px {colors.shadow-far}, …'`, `'circle, {colors.canvas} fill, 1.5px … ring'` (DESIGN.md L253, L392, L403ff). The design.md spec maps component keys to a value or a single reference. Code generation from this frontmatter (e.g. a Tailwind/shadcn theme) will need hand-parsing, and refs embedded in prose are easy to drift. *Fix:* split into atomic keys (`border-width`, `border-color`, `font`, `font-weight`, `color`), or keep each composite as a `note:` field beside atomic token keys.
- **medium** The spine does not cover non-text contrast (WCAG 1.4.11) for input boundaries. The "Why?" textarea is a paper fill with a 1px rule on canvas: 1.08:1 fill and 1.23:1 border in light, 1.31:1 in dark (DESIGN.md L334, L586). An empty required field is effectively invisible at rest. The contrast section lists only the focus ring and scroll thumb as non-text pairs (L522), yet EXPERIENCE.md L267 claims AA in both themes. *Fix:* give the resting border of `field` and `review-note-field` a ≥3:1 token (scroll-thumb is 3.4:1 on canvas) or justify the exemption explicitly. Then add the pair to the non-text contrast line.
- **medium** The print palette has no tokens. It is raw hex in prose (`#1A1A1A`, `#555555`, `#D0D0D0`, DESIGN.md L605), and the severity colours for print are never named: "Severity always has its word as well as its colour" (L610). The Typst template author for the flagship audit report (UJ-3) must guess. *Fix:* add `print-*` colour tokens (text, text-2, rule, plus four severity values with their contrast on white), or state "print severity = light-theme clay / amber / slate / forest-ink".
- **low** The wordmark token is 22px (DESIGN.md L111), which breaks "Nine sizes only … no others" (L108, L528) and the Don't "Intermediate sizes". The token also cannot express the Bold Italic it requires (no `fontStyle`). A theme generator that whitelists nine sizes will drop it. *Fix:* add "22 — wordmark only" as a stated exception and a `note: 'italic'` on the token.
- **low** Orphan tokens. `amber-wash` is described as "amber tag background" (L49), but no amber tag component exists. `forest-3` is "avatar gradient start" (L30), but there is no avatar component and no gradient end. *Fix:* either specify the avatar and amber tag, or remove the tokens.

## 3. Component coverage — adequate
Extracted 30 DESIGN.md Components rows and 20 EXPERIENCE.md Component Patterns rows. Most components in visual use have both a visual and a behavioural spec, under different names. Rows with real behaviour: Sidebar, Grouped list (List row + Group heading + Pager), Actively exploited marker, Status chip, Review panel + Review flow, Coverage-gap row, Exposure graph (with Inspector and Table), Freshness strip, Tabs, ⌘K palette.
### Findings
- **high** The unit of an "Issue" is undefined, so the status chip and the Needs-attention count are ambiguous. An Issues/Home row is one package-version × vulnerability across the fleet ("log4j-core 2.17.0 … 14 places", EXPERIENCE.md L351; the right column is one status chip, L69). The Exposure inspector shows a review status per software node (L86), and Software detail has its own Issues cell with Review (L75). Flow 2 step 6 records Not impacted for two services and Fix planned for the rest (L333). With one aggregated row, it is undefined what that row's single chip "reflecting the latest recorded decision" (L176) shows, whether the issue still counts as Not reviewed yet, and whether it leaves Needs attention. Open item 14 admits only that "review scope" is missing from the panel, not that the row/chip/count model depends on it. This blocks the data model, the VEX output (per product) and the badge count. *Fix:* commit the issue unit (fleet-level issue with per-software decisions, or per-software finding grouped for display). Then specify the aggregate chip for mixed decisions (e.g. "Mixed · 2 of 14 not impacted"), and specify how Needs attention and "not reviewed yet" count partial reviews.
- **medium** The Needs-attention rule is ambiguous to parse: "Not reviewed yet AND (Actively exploited OR Critical), plus licence decisions" (EXPERIENCE.md L57, L172). With 9 open licences of which 1 is not reviewed (memlog count model), "plus licence decisions" reads as 9, but the mock and Flow 4 show 1. The spine requires "the same number everywhere it appears" (badge, Home, All clear). *Fix:* rewrite as "Not reviewed yet AND (Actively exploited OR Critical OR Licence)".
- **medium** Components used in flows and states have no visual spec, and most have no behavioural spec either. These are: the copyable command/one-liner block with Copy (Empty Home setup L210, Flow 1 steps 1/5, Reports `cosign verify-blob`, Fingerprint "mono, copy"); the "Signature verified" block (L184; mock `.verified`); the in-progress audit-report row and the "adjustable after the click" window/scope/framework control (L183); the empty pre-setup Home. These are the trust moments of UJ-1 and UJ-3. *Fix:* add `code-block` (mono, Copy button, "Copied" feedback announced politely) and `signature-status` (verified / failed) rows to DESIGN.md Components. Add a Component Patterns row for report generation (in-progress row in Audit reports, how parameters are adjusted after the click, re-generation semantics).
- **low** Several DESIGN.md components have no behavioural row: Segmented control (does it update the URL? keyboard model?), Table (sort keys, keyboard sort, default order), Pager (keyboard, does `J`/`K` cross pages?), Fields/search (`/` focus, clear), Technical details (always open or collapsible?), Gauges & charts (text alternative, tooltip?). *Fix:* add one row each, or a single "Inherited shadcn behaviour unless stated" line naming them.
- **low** Behaviour of the signed-in user at the bottom of the sidebar (account menu, sign out) is not specified anywhere, and there is no avatar component despite `forest-3`. *Fix:* one Component Patterns row.

## 4. State coverage — thin
Walked Home, Software, Issues, Exposure, Reports, Settings, Help and ⌘K against empty, cold-load, focus, error, offline/stale, permission-denied and long-running states. Covered: pre-setup empty Home, Checking, cold-load skeleton, partial and zero answer in Exposure, All clear, Licences 0, stale source, registry unreachable, disconnected agent, air-gapped, read-only auditor, append-only history, audit report failure, palette no match, disabled. Acknowledged and accepted: focus/g-key frame (item 10), undrawn tabs (items 11–12), Help (item 20).
### Findings
- **high** The Exposure "Empty answer" (L214) and Flow 2's failure path (L335) can only say "No software has it — across the 3,176 … we've checked". No state covers an identifier the vulnerability data does not know yet: a CVE published hours ago that is not in the Grype DB, a typo, an unknown fingerprint or a package@version never seen. CVE day (UJ-2) is exactly when a CVE is in the news before the feed has it. The spine would then show a coverage-scoped all-clear for something it never evaluated. This breaks the signature rule ("the screen must never need a caveat it doesn't already show") and FR17's "definitive only when the data earns it". *Fix:* add a distinct state: "We don't have CVE-… in our vulnerability data yet (Vulnerability data updated 41 min ago). This is not a 'no'." It should include the feed age and a link to Sources. Also add a separate "not found" message for unknown packages and fingerprints.
- **high** No failure pattern exists for any mutation. That covers: Save and next in the review panel (which records audit evidence and auto-advances, L202), Decide later, Check again, Export, Generate audit report (start), Settings saves and connection tests, and a conflicting decision when two analysts review the same issue. In-product toasts-as-alerts are banned (L253), so story-dev has no permitted way to say "your decision was not saved". With auto-advance, a silent failure leaves a missing audit decision that nobody notices. *Fix:* add a "Save failed" row. Example: the review panel stays on the issue (no advance), shows an inline clay-wash error in the panel with the reason, and keeps the entered "Why?". Add a generic inline-error rule for other mutations and a stale-decision rule ("Changed by Marta at 14:05. Review again.").
- **medium** Several first-visit and zero states are missing. Issues with the default filter "Not reviewed yet" at 0, or a search with no match (likely the steady state for a well-run fleet). Exposure reached from the sidebar with no `q` (the URL in L48 always carries a query). Reports with no audit reports or exports yet. *Fix:* three rows in State Patterns with copy (e.g. Issues: "Nothing to review. 1,094 open, all reviewed. Show all statuses"; Exposure: a query prompt plus recent or Needs-attention suggestions).
- **medium** Only "Signature verified" is specified (L184, Flow 3 step 4). There is no state for a signature that fails to verify, a missing signing key, or a key mismatch. Signature verification is the core of FR25 and of the auditor's trust in UJ-3. *Fix:* add a "Signature does not verify" state (clay-wash band, which file, which key, no download hidden) plus copy for the offline command's failure output.
- **medium** The registry-unreachable state puts a lime Try again (L218) on Software, which already has the lime Add software (L77). That is two lime actions in one view, which is banned (L253, DESIGN Do's). The mock notes say Try again "is the one lime action", but the spine never says Add software turns grey. *Fix:* state "While an error band is shown, its recovery action takes the view's lime; the list's primary action turns grey."
- **low** Global states missing: session expired / re-authentication, control plane unreachable (self-hosted, single instance, NFR10), and a deep link to a Settings panel or a mutation URL by a role without access ("absent, not disabled" does not cover direct URLs). *Fix:* one row each.

## 8. Shape fit — adequate
DESIGN.md sections follow the canonical order (Brand & Style → Colors → Typography → Layout & Spacing → Elevation & Depth → Shapes → Components → Do's and Don'ts). Printed report sits as a subsection of Components. EXPERIENCE.md has every required default. Inspiration is present (triggered by the import and the memlog), and so is Responsive. The invented sections earn their place: Long-running operations, Theme, Printed report, Changes from …, Open items.
### Findings
- **high** The Responsive section leaves every viewport under 1280px undesigned (L283), yet the Accessibility Floor makes WCAG 2.2 AA "contractual" (L267). AA includes 1.4.10 Reflow (content usable at a 320 CSS px width, i.e. 1280px at 400% zoom) and 1.4.4 Resize text (200%). Fixed widths of 252 + 376/500 + detail cannot meet that without a collapse model. A common 1280px laptop screen also yields a viewport under 1280 once scrollbars and browser chrome are counted. Open item 6 frames this as an open breakpoint question, but it is a conformance blocker. It also shapes layout architecture: the routing, persistence and focus model of a three-column master-detail layout that collapses to one column. *Fix:* commit a collapse model now, at least: under 1280, the list and detail stack as two routes (list → detail with Back), and the sidebar becomes an icon rail and then a sheet. Note that graph and table are exempt from 2D scrolling under Reflow, but their surrounding UI is not.
- **medium** Single-key shortcuts (`J`, `K`, `/`, `x`, `?`, `g`+letter, L243–248) need a way to turn them off or remap them under WCAG 2.1.4 Character Key Shortcuts (Level A), unless they are active only on focus. Settings → Personal lists "keyboard shortcuts" (L99) but commits to neither. *Fix:* state "Single-key shortcuts can be turned off in Settings → Personal" (or that they are active only while the list or panel has focus).
