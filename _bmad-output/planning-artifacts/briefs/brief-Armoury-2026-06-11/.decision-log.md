# Decision Log — Armoury Product Brief

## 2026-06-11

- **Scope: servers/hosts OUT of v1.** Daniel initially described the fleet as "packages, servers and containers." On challenge, cut running-host scanning — too large a scope, different capability and competitive set than the artifact-centric stack (Syft/Grype/GUAC). Fleet = artifacts built/shipped (packages, container images).
- **Positioning discussion (in progress).** Daniel's instinct: detection insight and consistency/evidence are inseparable — "CVE database is free, how can we answer #2 without answering #1 first?" Working resolution under discussion: detection is necessary but commodity (free data, free scanners); the sellable, defensible layer is operational consistency + evidence. Not yet locked.
- **Source artifacts:** brainstorming session 2026-06-03, market research 2026-06-11 (validated wedge: enterprise ease and consistency; four sharpenings approved: evidence layer positioning, EU CRA GTM spearhead, post-NVD multi-source enrichment, self-hosted/air-gapped table stakes).
- **Stakes/audience: the brief is for Daniel himself** — solo, driving toward the PRD. No external audience to convince. Right-size accordingly: honest working document, not investor-grade.
- **Data sources phased:** v1 = static/registry (central SBOM+scan, no CI changes — "Option A") + live k8s cluster inventory (running image digests via API watch). Build-time integration ("Option B": blessed CI steps, build provenance, Sigstore) = roadmap. Daniel: "ultimately we need both, but A from day 1." Live = workload *inventory* only, NOT runtime behavior/eBPF/threat detection (boundary proposed by assistant, pending objection).
- **Success criteria reframed as a quality bar.** Daniel rejected business-metric success criteria ("this is all about building a good tool ... efficient audits and easy to surface threats"). Section renamed "What Good Looks Like": efficient audits, effortless threat surfacing, true 30-min deploy, trustworthy posture. Commercial model (open-core vs other) deliberately parked → addendum.
- **Scope outs confirmed:** SaaS-hosted offering out (self-hosted only to start); SAST out (explained as first-party code analysis — Daniel asked, accepted); auto-remediation PRs out until ~2027. **License compliance (Grant) moved IN for v1** — embedded from day one as supporting capability, not headline; integration mechanics open → PRD.
- **Users/buyer locked:** primary user = SecOps team at an SME, post-audit trigger ("just had a stressful audit, want next one faster"). Buyer = CTO, legal/compliance as champion. Form factor v1 = Helm chart into customer's k8s, self-hosted, <30-min to first posture view.
- **Positioning RESOLVED as a layering.** Daniel's hero scenario: "CVE X drops → Armoury tells you exactly which software and deployed fleet runs the affected version" (blast-radius query, the log4shell question). This insight is the *payoff*; the consistency layer (uniform SBOMs, lifecycle freshness, queryable graph) is the *prerequisite* that makes the payoff possible. Detection = commodity engine; consistency + evidence = defensible chassis; blast-radius insight = the demo. "Both" was correct — layered, not either/or.
