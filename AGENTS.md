# AGENTS.md

Rules for every coding agent working in this repository. `project-context.md` holds the universal
ethos; `docs/agent-readiness.md` holds the gate, CI design and decisions (D1-D14).

## Layout

```
Cargo.toml                 Cargo workspace (resolver 3, edition 2024)
proto/agent/v1/            agent <-> control-plane protocol (agent.proto)
agent-proto/               prost types generated from proto/ (build.rs, protox; no protoc)
control-plane/             `armoury` binary: web app + REST API on one origin, port 8080
  src/main.rs              wiring only
  src/httpapi/             router mount; server/generated/ is gen:api output (never edit)
agent/                     `armoury-agent` binary: read-only cluster watcher
api/openapi.yaml           the REST contract (source of truth)
web/                       SvelteKit SPA (adapter-static, SSR off), Tailwind v4, shadcn-svelte
  src/lib/api/             TS types generated by gen:api (never edit)
  src/lib/components/ui/   shadcn-svelte primitives only
  src/lib/{command,design,theme}/  palette, brand-layer components, tokens and fonts
  src/routes/              each surface owns its components, loaders and tests
  e2e/                     Playwright smoke tests
charts/armoury/            umbrella chart; charts/control-plane and charts/agent subcharts
okteto.yaml                Okteto build, deploy, dev container and e2e test container
mise.toml, mise-tasks/     pinned tools and every task (gate steps, CI tiers, dev loop)
.github/workflows/         ci.yml, build.yml, preview-cleanup.yml, renovate.yml (mise tasks only)
```

## Locality of Behaviour (ARCH25)

- Organise by capability, never by technical layer: no `models/`, `services/`, `repositories/`.
- No `utils/`, `helpers/` or `common/`. A shared thing earns a named home by capability, and only
  at its third use.
- At most three layers: entrypoint (handler) -> coordinator (capability) -> implementation.
- `main.rs` is the only place that constructs and wires dependencies. Pass dependencies
  explicitly; no globals or singletons (`static mut`, `OnceLock`, `LazyLock`, `lazy_static`).
- No `unwrap`/`expect` outside tests and startup (clippy denies them); use `?`. No `unsafe`
  (forbidden). `anyhow` only in `main.rs`; one `thiserror` enum per capability.
- Each file opens with a one-line purpose comment; keep files at 100-400 lines, split at 500+.
- Traits only at the third use or a real second implementation.
- Tests live next to the code (`#[cfg(test)]`, `*.test.ts`); cross-module Rust tests in `tests/`.
- Generated code is never edited by hand: change `api/openapi.yaml` or `proto/`, then run
  `mise run gen:api` (or rebuild for proto).
- Pin everything exactly: mise tools, `=x.y.z` Cargo requirements, exact npm versions, images
  by `@sha256` digest, actions by commit SHA. Commit the lockfiles.

## Development loop (PROC3)

Keep `mise run dev` running during every development step. It runs `okteto up`: Okteto builds
the images, deploys the chart into your namespace and runs the control plane with `cargo watch`
on `localhost:8080`. Verify each change against that deployment and with `mise run check`.
If the loop is unhealthy, fix it before writing code.

- `mise run check` is the handoff gate (fast tier, then cluster tier). `mise run check:fast` is
  for iteration only.
- `mise run e2e` runs the Playwright smoke test against `localhost:8080`.

## Explicit context (D3)

- Every `okteto` call passes `--context "$ARMOURY_OKTETO_CONTEXT"`. Commands without that flag
  (`namespace`, `context show`, `kubeconfig`, `registrytoken`) run with
  `OKTETO_CONTEXT="$ARMOURY_OKTETO_CONTEXT"`. The subcommand comes first.
- Every `kubectl` call passes `--context "$ARMOURY_KUBE_CONTEXT"` and an explicit `--namespace`.
- Never rely on the current Okteto or kube context: your kubeconfig also holds other clusters.
  `okteto up` and `okteto namespace` may change the current context; the tasks are unaffected.
- `helm` runs only local commands (`lint`, `template`, `package`); deployments go through Okteto.
- Never delete or destroy a namespace you did not create. In `ARMOURY_NAMESPACE`, delete only a
  Pod you created, by name. `okteto namespace create` always passes `--use=false`.
- No local container runtime, cluster or database: images build on Okteto, the test database is
  a Pod in your namespace.

## Version control

Use jj, never git. Agents run `jj new` and `jj describe`, and may set and push any bookmark except
`main` (forward moves only, no force or deletes; see `_bmad/custom/jj-vcs.md`). Only the user moves or
pushes `main`. There is no `CLAUDE.md`; this file is the agent context.
